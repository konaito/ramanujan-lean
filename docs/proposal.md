# Ramanujan in Lean
## ラマヌジャンが残した全公式をAIによって形式化する

### 1. 概要

インドの数学者シュリニヴァーサ・ラマヌジャンが残した数千の数学的公式を、Claude Codeと形式証明システムLean 4を用いて網羅的に形式化・検証するプロジェクト。

ラマヌジャンは、証明を伴わない膨大な数学的結果を残した。その死後、数学者たちは数十年にわたり、それらの証明と解釈に取り組んできた。

本プロジェクトでは、その数学的成果をAIエージェントによって再構築し、機械的に検証可能な数学ライブラリとして公開する。

単なる数学の形式化にとどまらず、AIが自律的に数学的知識を蓄積し、既存の知識を利用して新たな証明を生成する「数学ファクトリー」の構築を目指す。

### 2. 背景・問題意識

従来の数学では、発見・証明・理解のすべてを人間が担ってきた。

しかし、ラマヌジャンは数学的発見を先行させ、その証明を後世の数学者たちに委ねた。

現代では、AIによる推論と形式証明システムによる検証を組み合わせることで、証明という行為そのものを人間から切り離せる可能性が生まれている。

- 人間が発見し、AIが証明する。
- AIが証明し、機械が検証する。
- 蓄積された証明をAIが再利用し、さらに高度な証明を生成する。

この循環が成立すれば、数学的知識の蓄積は人間の理解速度に依存しなくなる。

ラマヌジャンの残した公式群は、分野の多様性、難易度、歴史的背景、既存の証明の充実度という点で、この仮説を検証するための優れた対象である。

### 3. プロジェクトの目的

**第一目標：ラマヌジャンの数学的成果の完全な形式化**

原典に記載された数学的結果を網羅的に整理し、正しい命題についてLean 4による機械検証可能な証明を構築する。誤記、誤った公式、解釈困難な記述についても分類・記録する。

**第二目標：自律型数学ファクトリーの構築**

人間が個別にプロンプトを与え続けなくても、AIが定理の形式化、証明探索、補題の構築、検証、修正を継続できるシステムを構築する。

**第三目標：AIによる数学研究のスケーラビリティの検証**

証明の成功率、コスト、依存関係、知識の再利用性を定量化し、AIによる数学研究がどの程度自律的に拡張可能であるかを明らかにする。

### 4. 対象範囲

- ラマヌジャンの主要な3冊のノート
- 失われたノート（Lost Notebook）
- 関連する書簡・論文
- 後世の数学者による証明・訂正・解釈
- 既存のLean・Mathlibにおける関連定理

対象分野には、無限級数、連分数、整数論、特殊関数、q級数、モジュラー形式、擬テータ関数、分割数などを含む。

### 5. システム構成

**① 原典データベース**

すべての数学的結果に一意のIDを付与し、以下の情報を管理する。

- 原典の画像・ページ番号
- 数式のLaTeX表現
- 数学的な意味と成立条件
- 既存の証明および参考文献
- Leanで形式化された命題
- 証明状況・難易度・依存関係
- 検証履歴・消費トークン・実行コスト

**② 形式化エージェント**

原典の数式と関連文献を読み込み、数学的な主張をLeanの定理宣言へ変換する。

定義域、収束条件、暗黙の仮定、記法の違いなどを明示する。

**③ 証明エージェント**

Claude Codeを用いてLeanコードを生成し、コンパイル結果とエラー情報をもとに自律的に証明を改善する。

必要に応じて既存文献を参照し、不足している定義や補題を追加する。

**④ 監査エージェント**

証明対象の命題が原典と一致しているかを独立して検証する。

命題の弱体化、不適切な仮定の追加、循環参照、未証明の公理への依存などを検出する。

**⑤ 検証・統合システム**

Leanカーネルによる検証とCIを通過した証明のみをメインブランチに統合する。

証明済みの定理や補題は共通ライブラリへ蓄積され、後続のエージェントから再利用可能になる。

### 6. 技術スタック

| 項目 | 使用技術 |
|---|---|
| 形式証明 | Lean 4 |
| 数学ライブラリ | Mathlib |
| AIエージェント | Claude Code |
| エージェント実行環境 | コンテナ・独立ワークツリー |
| バージョン管理 | GitHub |
| 自動検証 | GitHub Actions |
| 定理・依存関係管理 | SQLiteまたはPostgreSQL |
| 進捗可視化 | Webダッシュボード |

### 7. 自律実行モデル

エージェントには個別の証明方法ではなく、プロジェクト全体の目的、制約、評価基準を与える。

各エージェントは未処理の公式を選択し、形式化と証明を実行する。証明に失敗した場合は、問題を分解し、不足している補題や数学ライブラリを特定する。

不足する補題は新たなタスクとして登録され、別のエージェントによる証明対象となる。

これにより、固定されたタスクリストを消化するだけではなく、数学的な依存関係に応じて必要な作業が自律的に生成される仕組みを構築する。

### 8. 品質保証

Leanによるコンパイル成功だけでは、プロジェクトの成功とはみなさない。

以下を必須条件とする。

- `sorry`および`sorryAx`への依存禁止
- 独自の未証明公理の導入禁止
- 使用公理の監査
- 原典と形式化された命題の意味的一致
- 不必要な仮定の追加禁止
- 矛盾した仮定による自明な証明の排除
- 既存の証明・参考文献への出典明記
- 独立した再検証環境でのビルド成功

特に、AIが証明可能な別の命題へ問題を書き換えてしまうことを、最大の品質リスクとして扱う。

### 9. 実験計画

#### Phase 1：100公式による実証実験

複数の数学分野と難易度から100公式を選定する。

以下の条件で比較実験を実施する。

- 公式のみを与える場合
- 公式と既存の証明を与える場合
- 他のエージェントが構築した補題を再利用できる場合

証明成功率、形式化精度、実行時間、消費トークン、人間の介入回数を計測する。

#### Phase 2：数学ライブラリの自律構築

Phase 1で発見された不足ライブラリを整理し、共通基盤として構築する。

証明の蓄積によって、後続の定理の証明コストが低下するかを検証する。

#### Phase 3：全公式への拡張

原典の全結果を対象に、自律型エージェントを並列稼働させる。

定理の依存関係、難易度、推定コストを考慮し、処理順序を動的に最適化する。

#### Phase 4：未解釈・未解決領域への挑戦

既存文献によって十分に解釈されていない記述や、証明が確認できない数学的主張を抽出する。

実際に未解決であることを文献調査によって確認した上で、新たな数学的発見の可能性を探索する。

### 10. 評価指標

| 指標 | 評価内容 |
|---|---|
| 原典網羅率 | 全数学的結果の登録割合 |

| 証明完了率 | 品質基準を満たした証明の割合 |

| 自律完遂率 | 人間の介入なしに完了した割合 |
| 証明コスト | 1公式あたりのAPI・計算費用 |
| 知識再利用率 | 既存の補題を利用した証明の割合 |
| 学習曲線 | ライブラリの蓄積に伴う証明効率の変化 |

### 11. 成果物

- ラマヌジャンの数学的成果を網羅したオープンデータベース
- Lean 4による検証可能な数学ライブラリ
- 自律型数学エージェントの実行基盤
- 数学的依存関係を可視化したグラフ
- 証明状況を確認できる公開ダッシュボード
- AIによる数学の形式化・証明に関する実験報告書
- 他の数学者の著作にも適用可能な形式化フレームワーク

### 12. 将来的な展開

本プロジェクトで構築するシステムは、ラマヌジャンの公式に限定されない。

数学書、数学論文、歴史的な数学者の著作などを対象とする汎用的な形式化システムへ発展させることができる。

長期的には、数学の新たな成果が公開されるたびにAIがそれを形式化し、既存の数学的知識と接続し、機械検証可能な知識体系を更新し続ける基盤を目指す。

### 13. 本プロジェクトが問うもの

ラマヌジャンが残した数千の公式を、人類は数十年かけて証明してきた。

その仕事を、現代のAIはどれほどの時間とコストで再現できるのだろうか。

そして、AIが人間の理解を超える速度で数学的に正しい知識を蓄積するようになったとき、人間にとって数学を理解するとは、どのような行為になるのだろうか。

かつて、人間が証明を残さずに発見した数学を、今度は人間が証明を読まずに検証する。

Ramanujan in Leanは、その可能性を実証する試みである。
